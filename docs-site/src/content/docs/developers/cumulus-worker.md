Nubo Cumulus is a Cloudflare Worker named `nubo-cumulus`. It is Nubo's front door to the places Ubuntu packages and images come from: the request goes to Cloudflare's edge, the edge fetches from Ubuntu once and keeps a copy, and later requests are served from the copy. Files are not changed in any way. They stay Ubuntu's, signed by Ubuntu. The source is a single file of about 50 lines, `repo/cumulus-worker.js`. For what Cumulus means for users, see [Updates and the archive](/updates/).

## Routes and upstreams

The Worker is attached to the routes `archive.nubosuite.tech/cumulus*` and `/check`. The first path segment picks the upstream:

| Path | Upstream | Used for |
|---|---|---|
| `/cumulus` | `https://archive.ubuntu.com/ubuntu` | Ubuntu archive, amd64 |
| `/cumulus-arm` | `https://ports.ubuntu.com/ubuntu-ports` | Ubuntu archive, arm64 |
| `/cumulus-images` | `https://cdimage.ubuntu.com` | Installer images |
| `/cumulus-releases` | `https://releases.ubuntu.com` | Release ISOs |
| `/cumulus-cloud` | `https://cloud-images.ubuntu.com` | Cloud images |
| `/check` | none | Network connectivity check |

The table is the `UP` object at the top of the file. `APT` is a set holding the two apt paths, `cumulus` and `cumulus-arm`; the behaviour that is specific to apt applies only to those.

## Request flow

The `fetch` handler runs these steps in order.

1. **Method check.** Only `GET` and `HEAD` are allowed. Anything else gets `405 Method not allowed`.
2. **`/check`.** If the path starts with `/check`, the Worker answers at once with the body `NetworkManager is online`, the header `x-networkmanager-status: online` and `cache-control: no-store`. This replaces the connectivity check that Ubuntu's NetworkManager would send to Canonical. The `nubo-base` package points NetworkManager here (`base/20-connectivity-ubuntu.conf`).
3. **Route match.** A regular expression, `^/(cumulus|cumulus-arm|cumulus-images|cumulus-releases|cumulus-cloud)(/.*)?$`, splits the path into the upstream name and the rest. Anything that does not match is `404 Not found`. The upstream host is always one of the five fixed ones, so the Worker cannot be turned into an open proxy.
4. **`mirrors.txt`.** For the two apt paths, `/mirrors.txt` is generated by the Worker itself:

   ```text
   https://archive.nubosuite.tech/cumulus	priority:1
   https://archive.ubuntu.com/ubuntu	priority:2
   ```

   apt chooses at random among equal mirrors, so the file ranks them: Cumulus first, Ubuntu only as a fallback. apt reads this list because the sources use `mirror+https://archive.nubosuite.tech/cumulus/mirrors.txt`. The response is cached for 300 seconds (`public, max-age=300`).
5. **Root.** `/cumulus` itself returns a one-line description in plain text.
6. **Cache lifetime.** The Worker classifies the path:

   | Class | Test | Edge cache time |
   |---|---|---|
   | Immutable | path contains `/pool/` or `/by-hash/`, or ends in `.deb`, `.udeb`, `.dsc`, `.tar.*` or `.diff.gz` | 604800 s (7 days) |
   | Image | ends in `.iso`, `.img`, `.qcow2`, `.xz`, `.squashfs`, `.tar.gz`, `.manifest`, `.vmdk` or `.ova` | 3600 s (1 hour) |
   | Everything else | indexes, `Release` files, "current" links | 120 s |

   Published packages never change; the indexes and the "current" image links do, which is why they get short lifetimes.
7. **Upstream request.** The Worker fetches `UP[name] + rest + query string` with `GET` or `HEAD`, follows redirects, and forwards a few headers: `accept-encoding` (or `identity`), and `range`, `if-range`, `if-modified-since` and `if-none-match` when present. Forwarding `range` lets `apt` and image downloads resume. It sends its own `user-agent: nubo-cumulus`.
8. **Caching rule.** The request uses `cf: { cacheEverything: true, cacheTtlByStatus: {...} }`. Successful responses (200 to 299) are kept for the time from step 6, a `404` for 30 seconds, and server errors (500 to 599) are not cached at all.
9. **Response.** The body is passed through unchanged. The Worker adds `x-nubo-cumulus: 1` and removes any `set-cookie` header.

## Why it is built this way

- **Ubuntu stays the source of truth.** Nothing is rewritten, so Ubuntu's signatures still verify. The Worker adds speed and a single address, nothing else.
- **A failure must not stop a build or an update.** The `mirrors.txt` ranking means a Cumulus outage moves apt to Ubuntu's servers on its own. `ci/use-cumulus.sh` relies on that in every CI container.
- **Everyone behind Nubo gets the same cache.** Installer answer files, build scripts and `nubo-archive` all use the same paths.
- **Short lifetimes where needed.** The 120-second default keeps indexes fresh enough that a new Ubuntu update appears within a couple of minutes.

## Deploying

The repository holds the Worker's source but no deploy script for it. The header of `docs-site/worker.js` says the docs Worker is "deployed with the Cloudflare API", and the Cumulus Worker is deployed the same way. A deploy is two API calls: upload the script, then make sure the route points at it.

:::caution
The commands below are the shape of Cloudflare's public API, not a script from this repository. Check Cloudflare's current API reference before you run them, and keep the token out of your shell history. <!-- verify: exact deploy procedure used for nubo-cumulus -->
:::

1. Create an API token that can edit Workers scripts and Workers routes for the zone, and note your account id and the zone id of the domain.
2. Upload the script as a module:

   ```bash
   curl -X PUT "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/workers/scripts/nubo-cumulus" \
     -H "Authorization: Bearer $CF_API_TOKEN" \
     -F 'metadata={"main_module":"cumulus-worker.js","compatibility_date":"2026-01-01"};type=application/json' \
     -F 'cumulus-worker.js=@repo/cumulus-worker.js;type=application/javascript+module'
   ```

3. Attach the routes if they do not exist yet. One call per pattern:

   ```bash
   curl -X POST "https://api.cloudflare.com/client/v4/zones/$ZONE_ID/workers/routes" \
     -H "Authorization: Bearer $CF_API_TOKEN" -H "Content-Type: application/json" \
     --data '{"pattern":"archive.nubosuite.tech/cumulus*","script":"nubo-cumulus"}'
   ```

   Repeat for the `archive.nubosuite.tech/check*` pattern.

The Worker uses no bindings (no KV, no R2), so the metadata needs nothing beyond the main module.

## Changing the Worker safely

- Keep the five upstreams fixed. A Worker that proxies a host taken from the request is an open proxy.
- Keep `mirrors.txt` ranking Cumulus above Ubuntu. Taking away the fallback means a Cumulus outage stops updates and CI.
- Do not rewrite file contents or signatures.
- If you change a cache lifetime, think about the indexes first. A long lifetime on `Release` files delays updates for everyone.

## Verify

```bash
curl -fsSI https://archive.nubosuite.tech/check
curl -fsSL https://archive.nubosuite.tech/cumulus/mirrors.txt
curl -fsSI https://archive.nubosuite.tech/cumulus/dists/resolute/InRelease
```

The first should answer `200` with `x-networkmanager-status: online`. The second should list two mirrors. The third should answer `200` and carry the header `x-nubo-cumulus: 1`. Run the third twice; the second answer should be served from Cloudflare's cache (check the `cf-cache-status` header).

On a machine:

```bash
grep URIs /etc/apt/sources.list.d/ubuntu.sources
```

The line should read `URIs: mirror+https://archive.nubosuite.tech/cumulus/mirrors.txt` (or `cumulus-arm` on arm64).

## Troubleshooting

- **`apt update` on a machine fails with a mirror error.** Check `curl` against `mirrors.txt` from that machine. If Cumulus is down, apt should fall back to Ubuntu by itself; if it does not, the source file may point at a plain URL instead of the `mirror+` form.
- **`404` for a path that exists at Ubuntu.** The route name is wrong. arm64 uses `/cumulus-arm`, and the path after it follows `ports.ubuntu.com/ubuntu-ports`.
- **Old content after a fresh Ubuntu update.** Indexes can be up to 120 seconds old.
- **`405`.** Only `GET` and `HEAD` are served.
